A Word add-in for live, layered amendment display, built to
`amendment-display-addin-spec_rev.md`. It formats text to match
`three_layer_amendment_mockup_revised.docx`, and the Adopted and Failed keys fold up or
revert a layer with one keystroke and no confirmation.

**Download page:** `web/install.html` lets staff download `web/manifest.xml`.
That file is a copy of `manifest.xml`; after changing the manifest, copy it
into `web/` again before uploading.

**Staff documents** are in `docs/`: *Amendment Layers - User Manual.docx*
(full guide, installation and troubleshooting) and *Amendment Layers - Quick
Reference.docx* (two-page card for the meeting). Both are generated by
`docs/build-docs.js`; edit the text there and run `node docs/build-docs.js`
so they stay in step with the add-in.

## For the staff member at the meeting

| Do this | How |
|---|---|
| A new amendment is offered | Click **1**, **2** or **3** in the pane (2 = primary, 3 = secondary). Click again even if that level is already lit, because each click starts a new amendment. |
| Strike words | Select the words, then press **Ctrl+Alt+Shift+D** |
| Insert words | Put the cursor where they go, press **Ctrl+Alt+Shift+I**, then type. Or type the words first, select them, and press **Ctrl+Alt+Shift+I**. Either way, they are removed if the amendment fails. |
| Chair announces **adopted** | Click inside that amendment's text, then press **Ctrl+Alt+Shift+Y** ("yes") |
| Chair announces **failed** | Click inside that amendment's text, then press **Ctrl+Alt+Shift+N** ("no") |
| Undo a mistake | **Ctrl+Z**, as usual in Word |

The pane also has a button for each key, plus the legend.

**How it looks.** All text is black. Each level shows in its shading (none,
light blue, light purple), its strike lines (single, double, single), italics
at Level 3, and its underline (black single, blue double, purple dotted).
Struck text appears only once: striking plain text changes its style where it
stands, and striking text that a lower level *inserted* also strikes it where
it stands, keeping that level's underline. So "$75" inserted by the main
motion and struck by a primary amendment is double-struck, shaded light blue,
and still has its black single underline.

**What a vote does to struck text.** Failed removes only that level's
strikethrough, italics and shading, returning the words to how they were.
Adopted removes the words if the level above had inserted them; otherwise they
become a strike at the level above.

**Which amendment Adopted/Failed acts on.** The most recently created pending
amendment whose text contains the cursor. A cursor right at the edge of an
amendment's text counts as inside it. Its struck text and its new words both
count as inside it, so an amendment that only strikes, or only inserts,
resolves the same way.

**Amendments in several places.** One motion can make the same change in
several places, such as "Budget Committee" to "Finance Committee" wherever it
appears. Mark each place without clicking the level button in between; clicking
it starts a new amendment. A strike and the replacement words typed right after
it (with only spaces or punctuation between) form one place.
- **Adopted/Failed act on the place at the cursor only.** Press it in each
  place in turn. The pane reports how many places are still pending.
- **All places** (button in the pane): click it before Adopted/Failed, and that
  one keystroke applies to every place of the amendment at the cursor. It
  switches itself off afterwards. Click it again to cancel.

**Level 1.** Level 1 has its own Adopted/Failed:
- **Level 1 changes marked with the add-in** (Level 1 active) work exactly like
  Levels 2 and 3.
- **Level 1 markup already in the document as noticed** has no record of what
  came before it. Its old and new text are read from its formatting
  (underline = inserted, strikethrough = struck). To resolve it, make **Level 1
  the active level**, put the cursor in the change's struck or inserted words,
  then press Adopted or Failed. Only that change is resolved: the struck and
  inserted words around the cursor, with only spaces or punctuation between.
  Words or numbers in between separate two changes. Other changes in
  the same paragraph are left alone. To resolve several at once, select them
  all first. This works only while Level 1 is active, so a stray keypress
  during a Level 2 or 3 vote can't touch the Level 1 text.

**The order guard.** If you try to resolve an amendment while an amendment to
it is still pending *in the same place*, the pane says "Cursor in wrong
amendment level…", names the level still pending, and nothing changes. That
follows spec §7: flag it, don't guess. Amendments pending in other places,
elsewhere in the paragraph, or in other paragraphs don't block it.

## Hosting and installing

The add-in's files (the `web/` folder) are hosted on Netlify at
**https://amendment-layers.netlify.app**. Word loads them from there each time
the pane opens. `manifest.xml` tells Word that address. Netlify serves the
pane page as `index.html`, which is also its name in `web/`.

**Publishing an update.** Sign in to Netlify, open the *amendment-layers*
site, go to **Deploys**, and drag the `web` folder onto the drop area. Everyone
gets the new version the next time the pane opens. If the manifest itself
changes (its URLs, name or icons), raise `<Version>` in `manifest.xml`; Word
caches the manifest and may otherwise keep the old one.

**On this PC (development).** The add-in is registered with Word by pointing
Word's developer settings at this folder's `manifest.xml`. With Node.js
installed, run this in this folder:

```bash
npm run register
```

It also turns off the debugger pause and runtime log that `npm start` had
turned on. `npm run unregister` removes the add-in.

**On a staff member's PC.** No Netlify or GitHub account is needed. Put
`manifest.xml` in a shared network folder. On each PC, add that folder's
network path once under **File → Options → Trust Center → Trust Center
Settings → Trusted Add-in Catalogs**, tick **Show in Menu**, then restart
Word. The add-in then appears under **Home → Add-ins → Advanced → Shared
Folder**. If your organization has a Microsoft 365 business tenant, an
administrator can deploy it centrally instead.

Then open the bylaw document and click **Home → Amendment Layers**. After the
first time, the pane reopens by itself with any document that has used it.

**Why not localhost.** Serving from `https://localhost:3000` needs Windows to
trust a self-signed certificate. On this PC something (most likely the
security software) removes that certificate within minutes, so Word refuses
to load the add-in. `server.js` and `npm run local-server` remain for anyone
who wants to test local changes on a PC where the certificate stays trusted.

## Changing the keys

The keys are set in `web/shortcuts.json`. Edit them there, upload the `web`
folder to Netlify, raise `<Version>` in `manifest.xml`, and restart Word.
Ctrl+Alt+Shift+A and Ctrl+Alt+Shift+F were tried first for Adopted and Failed,
but on this PC something outside Word captures them before Word sees them. Word shows its own chooser if a key clashes with a Word command or
another add-in. To reset that choice, type **Reset Office Add-ins shortcut
preferences** in Word's search box. Custom shortcuts need Word for Windows
version 2408 or later.

## How it works

- `web/ooxml.js`: pure formatting transforms on Word's OOXML: strike, insert,
  fold up (adopted), and untracked Level 1 failed. No Office.js code.
- `web/engine.js`: the Word side. Each marked span is a hidden rich-text
  content control (spec §6), found by its tag, never by text search. Thread
  state (level, parent, status, and each span's `priorText` as OOXML) is
  stored in the document's add-in settings, so a pending amendment survives
  closing and reopening the file once the file is saved (spec §10).
- `web/taskpane.*`: the pane and keyboard-shortcut wiring (shared runtime).
- The spaces the add-in inserts between marked pieces carry an invisible
  `noProof` marker. That's how fold-up finds what it generated without
  guessing from the text. (Version 2's struck copies carry it too; fold-up
  still handles them.)
- With all text black, a run's level is read from its shading (struck text)
  or underline style (inserted text). Version 2's colored text is still read
  by its color.

## Known limits

- An amendment spanning more than one paragraph may not mark cleanly. Word can
  refuse to wrap a partial multi-paragraph selection, and the pane will say so.
- Selecting text that partly overlaps another amendment's span is refused.
  Select wholly inside it or wholly outside it.
- Untracked Level 1 resolution reads any underlined or struck text in the
  paragraph as Level 1 markup.
- The final change to real Track Changes is out of scope (spec §8).
